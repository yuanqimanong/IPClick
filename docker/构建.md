# 构建

构建上下文必须是仓库根目录（Dockerfile 需要 `pyproject.toml`、`uv.lock`、`src/`）：

> docker build -f docker/Dockerfile -t ipclick:latest .

或使用 buildx：

> docker buildx build -f docker/Dockerfile -t ipclick:latest .

基础镜像是 **python:3.14-slim**，可用 `--build-arg PYTHON_VERSION=` 换。

## 渲染引擎

默认镜像**自带浏览器渲染能力**：装 patchright 并把 chromium 本体也打进去，
拉下来就能用 `-a patchright` 渲染 JS 页面，不用在容器里再下载。

用 `--build-arg ENGINE=` 换引擎：

| ENGINE | 装什么 | 镜像大小 |
|---|---|---|
| `patchright`（默认） | Playwright 的反检测分支 + chromium 本体 | 约 2.0 GB |
| `camoufox` | Firefox 内核，反检测最彻底 | 约 2.5 GB |
| `linux` | 上面两个都装（对应 pyproject 的 `[linux]` extra） | 约 3 GB |
| `none` | 不装浏览器，只有 curl_cffi | 约 0.4 GB |

> docker build -f docker/Dockerfile --build-arg ENGINE=none -t ipclick:slim .

不需要渲染 JS 页面就用 `ENGINE=none`——省掉 1.5 GB 和几分钟构建时间。

两个和引擎有关的环境变量已经在镜像里设好，**不要在 `docker run` 时覆盖它们**，
否则引擎找不到自己的浏览器：

- `PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright` —— patchright / playwright 的本体位置
- `XDG_CACHE_HOME=/opt/cache` —— camoufox 的本体位置（它认这个变量，没有 `CAMOUFOX_HOME`）

浏览器本体放在 `/opt` 而不是某个用户的家目录，是为了让镜像里的非 root 用户也读得到。

> **镜像里装不了新组件。** 运行阶段是 slim 镜像 + uv 建的 venv，既没有 pip 也没有 uv，
> 所以 `ipclick component install` 和 Web 端的组件安装按钮在容器里用不了（会明确告知，
> 不会假装成功）。要换引擎请重新构建镜像。

# 运行

> docker run -d -p 5555:9528 --name ipclick ipclick:latest

> ### config.toml
> 镜像以非 root 用户 `ipclick` 运行，配置目录是 `/home/ipclick/.ipclick/`
>
> docker run -d -p 5555:9528 --name ipclick -v /【你的路径】/:/home/ipclick/.ipclick/ ipclick:latest

# 校验

> docker run --rm ipclick:latest ipclick --version

> docker run --rm ipclick:latest ipclick config-info

## 推送到 Docker Hub

Docker Hub 只认 `用户名/仓库名`。裸的 `ipclick:latest` 推不上去——它会被当成官方
library 镜像，然后 403。先改名，再推：

> docker login

> docker tag ipclick:latest yuanqimanong/ipclick:2.0.0

> docker tag ipclick:latest yuanqimanong/ipclick:latest

> docker push yuanqimanong/ipclick:2.0.0

> docker push yuanqimanong/ipclick:latest

`ENGINE=none` 的 slim 镜像单独挂 tag，不占用 `latest`（`latest` 留给自带浏览器的默认镜像）：

> docker tag ipclick:slim yuanqimanong/ipclick:2.0.0-slim

> docker tag ipclick:slim yuanqimanong/ipclick:slim

> docker push yuanqimanong/ipclick:2.0.0-slim

> docker push yuanqimanong/ipclick:slim

同一个镜像挂两个 tag 不会传两遍，第二次 push 全是 `Layer already exists`，秒完。

> **第一次 push 会自动建仓库，默认 public。** 要私有就先去 hub.docker.com
> 手动 Create repository 选 Private，再推。

`docker login` 会走 Docker Desktop 的浏览器登录。命令行登录请用 Access Token
（Hub → Account settings → Personal access tokens），别在命令行里贴密码——会进 shell 历史。

推完拉下来验证一遍：

> docker run --rm yuanqimanong/ipclick:2.0.0 ipclick --version

### 多架构

Windows 和 Intel Mac 上构建出来的是 **linux/amd64**，arm64 的服务器和 Apple Silicon
拉下去跑不了（靠 qemu 能跑，但慢得没法用）。要一份 tag 通吃两个架构必须用 buildx，
而且**必须直接 `--push`**——manifest list 存不进本地 `docker images`，
不加 `--push` 就等于白构建：

> docker buildx create --use --driver docker-container

> docker buildx build -f docker/Dockerfile --platform linux/amd64,linux/arm64 -t yuanqimanong/ipclick:2.0.0 -t yuanqimanong/ipclick:latest --push .

默认的 `desktop-linux` builder 是 docker driver，出不了多架构镜像，所以上面那句
`buildx create` 不能省。arm64 上装 chromium / camoufox 要慢好几倍，
只给 `ENGINE=none` 的 slim 出多架构会省事很多。
